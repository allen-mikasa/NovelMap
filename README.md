# NovelMap Engine - 小说地图可视化引擎

> **一卷小说，一张地图**

基于 TRAE SOLO 构建的小说地图可视化引擎。用户只需上传小说文本，AI 即可自动提取地名、空间关系、人物与事件，并生成交互式世界地图（真实地理 / 虚构地形双模式），让每本小说的虚构世界跃然纸上。

---

## 效果展示

### 真实地理模式 —《三国演义》

AI 自动识别真实地名并定位到地图上，点击地点可查看关联事件与人物。

![三国演义 - 真实地理模式](images/demo_real_map.png)

### 虚构世界模式 —《剑来》

为玄幻/仙侠小说生成程序化地形，基于空间关系自动排布地点，支持势力区域着色与生物群落渲染。

![剑来 - 虚构世界模式](images/demo_fictional_map.png)

## 功能特性

- **AI 智能分析** — 自动提取地名、空间关系、人物、事件，支持长文本分段处理
- **双模式地图** — 真实地理模式（历史小说）+ 虚构世界模式（玄幻仙侠）
- **虚构地形生成** — Perlin Noise 程序化地形 + 生物群落着色（沙漠/雪原/草原/森林等）
- **力导向布局** — 基于空间关系的自动地点排布，支持区域方位识别
- **势力区域可视化** — 凸包多边形 + 鼠标悬浮提示 + 区域名称标注
- **图层控制** — 势力区域 / 关系连线 / 地名标注独立开关
- **文件上传** — 支持 `.txt` / `.md` 格式小说文件，最大 50MB
- **实时进度** — WebSocket 推送 AI 分析进度
- **地点详情** — 点击标记查看描述、关联事件、相关人物

## 快速开始

### 前置条件

- Python 3.10+
- 智谱AI API Key（[免费申请](https://open.bigmodel.cn/)，使用 GLM-4-Flash 免费模型）

### 安装依赖

```bash
pip install fastapi uvicorn websockets zhipuai pillow numpy
```

### 启动服务

```bash
cd novel-map-demo
uvicorn app:app --host 0.0.0.0 --port 8000
```

### 使用

1. 打开浏览器访问 `http://localhost:8000`
2. 在顶部输入框填入智谱AI API Key，点击「验证」
3. 粘贴小说文本或点击「上传文件」加载 `.txt` 文件
4. 点击「开始分析」，等待 AI 提取完成
5. 在左侧面板查看分析结果，在地图上浏览交互式世界地图

## 开发背景

在学习和生活中，我发现身边的许多同学都有阅读小说的习惯，但是目前的网络小说大多信息量巨大，很容易忘记前文情节，对于小说的世界观也难以精准记忆。恰好我正在学习使用 AI 工具和 vibe coding，于是我便想着，能否用 AI 打造一款能让小说可视化的工具？

带着这个想法，我开始了 NovelMap Engine 的开发——用户只需上传小说文本，AI 就能自动提取地名、空间关系、人物与事件，并生成一张可交互的世界地图。整个项目从需求构思、前后端开发到调试优化，我全程借助 TRAE SOLO 以对话驱动的方式完成，亲身体验了 AI 辅助开发的完整流程，也深刻感受到了 vibe coding 带来的效率提升。

## 实践总结

### 任务拆解

项目分为 **4 个递进阶段**，每个阶段独立验证：

| 阶段 | 目标 | 验证标准 |
|------|------|---------|
| P0 基础框架 | 搭建前后端骨架，跑通全链路 | 地图能渲染标记 |
| P1 AI 分析 | 接入大模型，自动提取实体 | 输入文本 → 输出结构化数据 |
| P2 真实地理 | 支持真实世界坐标 | 三国演义地点定位到实际地图 |
| P3 虚构世界 | 生成虚构地形和力导向布局 | 玄幻小说地点正确排布 |

### SOLO 的核心作用

**我负责"想"，SOLO 负责"做"**——从项目搭建、功能开发、Bug 修复到 UI 优化，全部代码由 SOLO 生成，我只用自然语言描述需求和反馈问题。

### 踩过的坑

| 问题 | 根因 | 解法 |
|------|------|------|
| 方位反转（南疆跑到上方） | 角度映射用了数学坐标系，y 轴方向错误 | 改为方向向量映射 |
| 图层控制消失 | 面板放在 48px 高的 navbar 内被裁剪 | 移到左侧面板 |
| 地点标记不渲染 | `switchToRealMap` 的 early return 导致状态不一致 | 移除守卫，每次强制重建 |
| 地点直线排列 | 同区域地点初始化在 ±100 正方形内 | 改为极坐标圆形分布 |
| 地形颜色无变化 | 只从区域名检测地形，"天启帝国"无关键词 | 增加从地点 type/description 提取 |
| 中州被推偏 | 方位关系力远大于中心引力 | 给含"中"的区域增加额外中心引力 |

### 可复用的方法

- **截图 + 现象描述 → AI 排查 Bug**：比自己翻代码高效得多
- **小步迭代，每步可验证**：不一次性重写，而是拆成独立可验证的小任务
- **从现象倒推根因**：描述"看到了什么"，让 AI 沿执行链路追踪
